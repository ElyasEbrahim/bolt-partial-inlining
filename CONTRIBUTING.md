# Contributing

Thank you for your interest in improving partial inlining for BOLT. Bug
reports, test cases, measurements on other hardware and code contributions are
welcome.

## Reporting issues

Please open a GitHub issue and include

* the `llvm-bolt` command line and the `BOLT-INFO: partial inlining` lines of
  its output (`-v=1` lists every transformed call site, `-v=2` also the reasons
  why callees were rejected);
* for miscompilations: the smallest input binary and profile that reproduce
  the problem, and the output of `--print-partial-inline
  --print-only=<caller>`. `--partial-inline-max-sites=N` and
  `--partial-inline-skip=<functions>` help to bisect the call site;
* for performance results: CPU, OS, compiler and BOLT options.

## Repository layout

| Path | Content |
|---|---|
| `patches/` | the LLVM patch and the LLVM commit it applies to |
| `docs/` | design document |
| `benchmarks/` | microbenchmarks and real-world workload build scripts |
| `scripts/` | profiling, variant generation, benchmarking and reporting |
| `results/` | the published measurements, generated by `scripts/run_experiments.sh` |
| `docker/` | evaluation image and development environment |

## Changing the BOLT pass

The implementation lives in the LLVM tree; this repository carries it as a
patch. To work on it:

```bash
git clone https://github.com/llvm/llvm-project.git && cd llvm-project
git checkout -b partial-inlining "$(cat ../bolt-partial-inlining/patches/LLVM_COMMIT)"
git am ../bolt-partial-inlining/patches/0001-*.patch
# ... edit, build, test ...
git format-patch -1 -o ../bolt-partial-inlining/patches/
```

`docker/dev.Dockerfile` provides the toolchain used for development (clang and
lld 23, ninja, valgrind, clang-format). Build and test with

```bash
cmake -G Ninja -S llvm -B build -DCMAKE_BUILD_TYPE=Release \
  -DLLVM_ENABLE_ASSERTIONS=ON -DLLVM_ENABLE_PROJECTS=bolt \
  -DLLVM_TARGETS_TO_BUILD="AArch64;X86" \
  -DBOLT_CLANG_EXE=$(which clang) -DBOLT_LLD_EXE=$(which ld.lld)
ninja -C build check-bolt
```

Requirements for changes to the pass:

* follow the [LLVM coding standards](https://llvm.org/docs/CodingStandards.html)
  and format the changed lines with `git clang-format`;
* add or update lit tests under `bolt/test/` (`AArch64/partial-inline-*.s`,
  `X86/partial-inline.s`, `runtime/AArch64/partial-inline.c`); a fix for a
  miscompilation needs a test that fails without the fix;
* `check-bolt` must not change the result of any existing test;
* without `--partial-inline` the output of `llvm-bolt` must stay
  byte-identical to upstream (`scripts/verify_flag_off.sh`).

## Changing the evaluation

* Scripts must pass `make lint` (shellcheck, pyflakes).
* Published results must come from one complete run of
  `scripts/run_experiments.sh` in the image built from the same commit
  (`make image experiments`); do not mix results of different runs.
* Workload sources are downloaded at build time and pinned by SHA-256 in
  `benchmarks/realworld/build.sh`.
* Workloads must run deterministically under a profile: fix hash seeds and
  random seeds, and keep the training runs in `scripts/bolt_variants.sh`
  under `setarch -R` (in Docker this needs `--security-opt seccomp=unconfined`).
  The same profile must always produce the same BOLT output.
